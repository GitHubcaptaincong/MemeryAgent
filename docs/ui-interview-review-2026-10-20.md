# 面试展示界面检查

检查日期：2026-10-20。

用户已明确：面试主要展示微信小程序。以下先列小程序建议，再保留网页备用演示的检查结果。

检查对象：当前小程序和 H5 源码，以及 https://githubcaptaincong.github.io/MemeryAgent/ 公开演示。

验证范围：
- 在浏览器中实际打开线上网页，检查 1440 × 900 桌面视口和 390 × 844 手机视口。
- 点击展开结果、查看知识集、知识集列表、新建对话、复习导航。
- 本地使用 `VITE_PUBLIC_DEMO=true` 执行前端生产构建，结果通过。
- 未验证微信真机、真实模型、生产数据库或完整真实业务闭环。
- 本次只检查和记录建议，没有修改产品代码或发布部署。工作区原有未提交修改保持不变。

## 微信小程序：优先优化项

本节基于当前源码分析，尚未在微信开发者工具或真机中复现。线上小程序是否与当前工作区一致也未核对。

### 优先 1：保留任务完成后的整理过程

`miniprogram/pages/capture/capture.wxml:130` 把事件列表放在 `busy` 条件内，任务到达待确认、完成或失败状态后会将 `busy` 和 `tasksExpanded` 设为 false（`capture.js:629` 起）。因此过程区会隐藏，失败时也难以在结果旁回看发生了什么。

建议：结果卡常驻“整理过程”入口，点开查看真实事件、工具结果与证据校验摘要。默认展示“读取材料 → 生成知识点 → 校验证据 → 等待确认”，具体事件可展开。这个入口最有利于解释项目的 Agent 工程能力。

### 优先 2：确认操作外置，知识点逐条展开

`capture.wxml:110` 中，所有知识单元详细内容与确认按钮位于同一展开区，按钮排在全部详情之后。

建议：卡片常驻“待确认 / 已加入复习”和主要操作；每个知识点单独展开。确认前支持审阅，确认后提供“立即复习”。避免材料较长时需要滑过整段详情才能继续。

### 优先 3：原文证据变成可定位的内容

整理结果与复习答案目前主要展示 `evidence[0].quote`（`capture.wxml:115`、`review.wxml:104`），没有同位置的完整原文查看与高亮交互。

建议：点击“查看依据”打开原文抽屉或独立页面，高亮引用区间，支持多条证据切换。把引文字号从偏小的辅助文本提升到可读正文层级。比单纯美化聊天气泡更能展示证据追溯价值。

### 优先 4：复习页按步骤组织，保持评分入口可见

当前顺序是问题、回答、答案对照、AI 评估、最终评分；AI 缺失点较多时，评分区会被推向更下方（`review.wxml:107`、`:130`）。

建议：明确“作答 → 对照 → 自评”的步骤；提交回答后把自评按钮放在固定操作区或提供固定跳转入口，AI 详情可折叠。保留已有的四档下次复习时间预览、AI 不覆盖自评的边界。

另有交互可靠性问题需要优先复现：
- `review.js:207` 的 `selectCard` 会直接清空已输入答案，没有按卡保存草稿。
- 请求期间队列项仍可点击；`submitAnswer` 返回时直接设置 `answerResult`，未判断当前卡片是否仍为请求发起时的卡片。慢网络下切题可能让旧题结果出现在新题下。
- 建议保存每题草稿，请求期间限制切题，或通过卡片/请求标识丢弃过期响应；在真机限速网络下验证。

### 优先 5：提高首页的任务辨识度

欢迎页提供“总结文章 / 记录知识 / 整理想法 / 问一个问题”，但 `capture.js:218` 的快捷操作仅更新 placeholder 并聚焦输入框。

建议：突出“把材料变成可追溯、可复习的知识点”，提供清晰的粘贴材料、添加链接入口。可以加入“一份示例材料”帮助展示，但应由用户明确触发提交，不自动调用真实模型。

“已整理 N 条记忆”建议改为“生成 N 个知识点”，与另一个“长期记忆建议”区分。长期记忆卡可以说明“为什么建议记住”和“将用于什么”，帮助解释审批机制。

### 优先 6：知识编辑改为完整表单

`review.js:422` 起通过两个连续的可编辑原生弹窗修改问题和答案。建议使用独立编辑页或底部面板，同时展示问题、多行答案、保存/取消和原文依据。

### 优先 7：调整导航与设置归属

当前底部是整理、复习、提醒，知识集藏在复习二级标签，AI 评估开关又在提醒页。

小范围调整可先把“提醒”改为“设置”，内部区分复习提醒与 AI 辅助。若知识管理是主要使用场景，再考虑底部“整理 / 知识库 / 复习 / 设置”，统计继续从复习入口进入。无需为了面试立即增加大量页面。

### 小程序推荐首轮范围

首轮聚焦：任务过程回看、确认操作外置、原文证据定位、复习步骤与切题保护。之后再统一字号、卡片间距、图标与编辑表单。

真机补验：键盘弹起后输入/发送可见；长文本展开与滚动；多知识点确认；任务中切后台再返回；弱网提交时切题；AI 超时仍可自评；评分后下一题和下一次时间正确；微信提醒授权与实际发送分别验证。

面试演示顺序：粘贴一小段熟悉的技术材料 → 看整理阶段 → 审阅知识点和原文依据 → 确认 → 回答一道题 → 查看 AI 建议并自评 → 展示下次复习时间。提前准备一份真实完成的案例，现场模型等待较久时可以继续讲解已有结果。

## 网页备用演示：实际复现的问题

### 1. 知识集入口无法展示已生成内容

线上复现：
1. 整理页点击“查看全部”。
2. 点击“查看知识集”。
3. 页面显示“公开演示模式不会连接后端、写入数据或调用模型。”，同时展示“0 组”“还没有知识”。
4. 直接进入“复习 → 知识集”也出现同样结果。

原因：`frontend/src/App.vue:185` 的 API 包装器会阻止公开演示请求，但 `showKnowledgeSets` 和 `openKnowledgeSet` 未提供本地示例分支（约 682、702 行）。

建议：为知识集列表、详情提供与现有草稿一致的本地示例数据；编辑和删除明确禁用或实现仅内存交互。让“整理结果 → 知识集 → 复习”连贯可演示。

### 2. 新建对话把演示带入无法继续的空状态

线上点击右上角新建按钮，示例结果被清空，出现欢迎页；输入框和发送按钮仍禁用。

原因：`newConversation` 直接清空状态（`frontend/src/App.vue:346`），而公开模式禁止输入（约 1201 行）。

建议：公开模式改为“重置示例”或“切换示例”；保留随时返回完整案例的入口。历史对话读取也需要本地示例分支。

### 3. 整理页顶部说明被遮挡

线上手机视口测量：演示提示区域从 y=66 延伸至约 y=145，聊天区域却从 y=104 开始，覆盖了提示正文。

原因：`frontend/src/style.css:453` 写死 `.agent-chat-layout { top: 104px; }`，无法适应提示实际高度。

建议：用正常文档流配合 flex/grid 分配剩余高度；避免根据估算的提示高度定位聊天容器。

### 4. 复习选中标签对比度异常

线上“复习 / 知识集”中，选中的“复习”显示白字，却缺少预期深色背景。

原因：`frontend/src/style.css:570` 起使用 `--ink`、`--paper`、`--line`、`--muted`、`--accent`、`--soft`，当前样式未定义这些变量。选中态保留白字，背景声明失效。

建议：统一定义颜色变量并核对知识集卡片、边框、链接和选中状态；合并早期绿色样式与后续蓝色移动端样式。

### 5. 示例统计的时间与数量不一致

线上“近 7 天”“未来 7 天”仍显示 2026 年 8 月的固定日期；页面同时显示“全部到期 2”和“还有 5 张超出今日软上限”。

源码：`frontend/src/demoData.js:134`、`:158`、`:172`。

建议：由同一份示例卡片和日期基准派生队列、计数与图表；选择固定场景日期就明确标注，选择相对当前日期就统一计算。AI 评估也应明确标为预置反馈，避免让任意输入都看起来获得了真实模型评估。

## 增强面试展示效果

### 6. 为电脑共享屏幕提供桌面布局

实际 1440px 宽窗口里，应用宽度仍为 460px；来源是 `frontend/src/style.css:343`。这是模拟手机的设计，但限制了电脑演示的信息量和字号。

建议：
- 桌面采用左侧导航/历史、中间任务内容、右侧原文或执行记录的布局。
- 手机保持单列、底部导航。
- 复习页将当前问题与作答区放在首屏，将统计移到独立入口或下方。

当前桌面截图里，复习页首屏主要是提示、标题、统计和队列，实际问题及输入框位于下方。

### 7. 保留任务完成后的执行记录

源码中工具事件、校验摘要和处理事实只放在 `v-if="busy"` 的区块内（`frontend/src/App.vue:1184`）；任务结束后没有同等的回看入口。打开历史会话还会清空当前事件列表（约 280 行）。

建议：在结果卡增加“查看整理过程”，显示实际持久化事件、工具结果摘要、校验状态和恢复记录。公开演示使用明确标注的示例记录，不模拟真实实时执行。

面试价值：可以直接解释材料读取、证据定位、结构校验、失败恢复，而不必只展示聊天结果。展示业务执行记录，不展示或伪造模型隐式思维链。

### 8. 让证据和确认动作更直接

当前结果先展示两条标题，展开后显示解释、问题和第一条引文；“确认并加入复习”也位于展开区内部。

建议：
- 草稿状态、知识点数量、确认按钮放在结果卡常驻区域。
- 点击“原文依据”打开原文并高亮对应片段。
- 原文证据与用户后来编辑的答案保持清晰区分。
- 已确认结果提供直接“开始复习”入口。

### 9. 统一产品语言与编辑方式

- “已整理 N 条记忆”实际指知识单元，与另一个“长期记忆建议”概念容易混淆。建议改为“生成 N 个知识点”。
- 欢迎页的“问一个问题”“总结文章”等按钮目前只改变输入提示，不能单凭这些按钮体现独立模式。
- 知识编辑使用连续 `window.prompt`（`frontend/src/App.vue:714`、`:725`）；建议改为带标题、问题、多行答案和保存反馈的抽屉。
- 复习页“本阶段”“当前 MVP”等开发过程用语可换成直接的用户说明。

### 10. 同步对外说明

README 仍写最多 10,000 字、不支持网页链接；当前前端允许 50,000 字并提供链接入口。展示前应结合后端当前实现更新能力说明，避免仓库介绍与页面矛盾。

## 建议实施顺序

1. 修复公开演示分支、遮挡、颜色变量、示例日期与计数，保证观众点击现有入口时流程完整。
2. 增加桌面响应式布局，收紧复习首屏，统一字号、颜色和间距。
3. 增加原文定位和执行记录回看，突出项目已有技术能力。
4. 最后改善知识编辑、空状态、示例切换和重置。

建议准备一条约 3 分钟的演示路线：

材料 → 知识点与原文依据 → 整理过程 → 确认后的知识集 → 主动回答 → 答案对照与自评 → 下一次复习。

公开站点应明确说明使用示例数据；真实生成另用经过预检的真实环境展示。
