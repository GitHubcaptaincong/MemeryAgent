# 阶段三：复习、作答与提醒闭环

## 本阶段目标

把已确认的知识草稿真正变成可练习内容，跑通：

```text
确认草稿
  → 创建到期复习卡
  → 用户先独立回答
  → 展示答案要点和原文证据
  → 用户最终自评
  → 调度器计算下次到期时间
```

## 已实现模块

### 1. 复习卡投影

- 每个已确认知识单元对应一张 `review_card`。
- `(user_id, draft_unit_id)` 唯一，重复确认不会重复建卡。
- 保存当前到期时间、间隔、复习次数、遗忘次数和调度状态。
- 这是可重建的当前状态，不承担历史审计职责。

### 2. 不可变复习事件

- `answer_submitted`：保存用户回答、提交时的复习次数和关联尝试 ID。
- `review_rated`：保存最终用户评分、FSRS ReviewLog、调度前后 Card 状态和下次到期时间。
- 事件在应用层只追加、不原地改写；`idempotency_key` 防止网络重试产生重复记录。
- `(card_id, correlation_id, event_type)` 唯一约束防止同一尝试被并发推进两次；卡片行锁和提交时复习次数共同拦截过期尝试。

### 3. 调度适配器

当前使用官方 `py-fsrs 6.3.1`，调度器版本为 `fsrs-6.3.1-v1`，配置版本为 `fsrs-default-no-fuzz-v1`：

- 评分 1–4 直接映射 FSRS 的 Again、Hard、Good、Easy。
- 保留官方 1 分钟、10 分钟学习步骤和 10 分钟重学步骤。
- 目标记忆率为 0.9；尚未根据个人历史训练参数。
- 关闭随机抖动，使同一不可变历史能够得到相同调度结果。
- 客户端不再写死间隔；队列接口为当前卡片返回四档真实预览。

`scheduler_state` 保存带算法、库、配置版本的 FSRS Card 字典；`due_at` 等字段只作为查询投影。旧 `mvp-review-v1` 卡片在下一次评分时按历史事件重放迁移，事件数量不一致时停止迁移并返回冲突，避免丢失学习状态。

### 4. 用户界面

- 整理页：输入材料、查看 Agent 审计轨迹、确认草稿和审批长期记忆。
- 复习页：查看今日队列、四档动态间隔、回答开放题、对照答案与证据、完成自评，并查看下一次到期和最近复习。
- 提醒页：设置启用状态、每日时间、数量上限、逾期策略和时区。

## API

```text
GET  /api/v1/review/queue
GET  /api/v1/review/overview
GET  /api/v1/review/history
POST /api/v1/review/cards/{card_id}/answers
POST /api/v1/review/cards/{card_id}/ratings
GET  /api/v1/reminders/preferences
PUT  /api/v1/reminders/preferences
```

## 明确边界

- 用户评分是本阶段调度的最终输入，尚未接入 AI 语义判分。
- 当前使用通用 FSRS 默认参数，不代表已经训练出个人最优参数。
- 提醒偏好已持久化，但浏览器通知、系统通知、邮件或微信推送尚未实现。
- 当前应用重新打开后能看到到期队列；关闭页面后不会主动弹出通知。

## 下一阶段建议

1. 增加 AI 回答评估：只给依据和建议等级，用户仍可覆盖。
2. 增加定时扫描与微信订阅消息，完成关闭应用后的主动提醒。
3. 接入微信身份并验证多用户数据隔离。
4. 数据量足够后离线训练个性化 FSRS 参数，并用历史事件显式重算。
5. 增加正确率趋势、薄弱知识聚类和每日负载平衡。
